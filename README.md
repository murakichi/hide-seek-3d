# HIDE & SEEK 3D

ブラウザで動く見下ろし型の 3D 鬼ごっこ。準備時間に障害物を動かして隠れ場所を作り、
放たれた鬼から逃げ切る。OpenAI の「かくれんぼ」実験のイメージを、
その場で遊べるアクションゲームに落とし込んだもの。

## 遊び方

```bash
npm install
npm run dev
```

1 on 1 / 2 on 2 / 3 on 3 と、自分の陣営（逃げる / 鬼 / 観戦）を選んで開始する。

### 操作

| 入力 | 動作 |
| --- | --- |
| `WASD` / 矢印 | 移動 |
| `Shift` | ダッシュ（スタミナ消費） |
| `Space` | ジャンプ |
| `E` / 左クリック | 箱をつかむ（つかんだまま歩けば運べる。跳べば持ち上がる） |
| `F` / 右クリック | ロック / 相手のロック解除 |
| `Q` | 煙幕を撒く（逃げる側・2 回まで） |
| マウス | 視線の向き |
| `1` `2` `4` `8` | 早送り（観戦中・捕まったあと） |

画面右上の **ログを保存** で、その試合の出来事をテキストファイルに落とせる。
試合中でも決着後でも押せて、押した時点までの全部が入る。
先頭にシードと再現コマンドが付くので、観戦した試合はそのままヘッドレスで再生できる。

```
# シード     4881245
# 再現       npm run trace -- --hiders 2 --seekers 2 --seed 4881245 --interval 3
```

中身は `npm run trace` と同じ書式（`src/sim/recorder.ts` を共有している）。

### ルール

- **準備フェーズ（32 秒）** — 逃げる側だけが動ける。鬼は中央のケージに閉じ込められ、
  外を見ることもできない。この間に箱を運んで囲い、ロックして固定する。
- **追跡フェーズ（70 秒）** — 鬼が放たれる。触れられた逃走者はその場で脱落。
- **決着** — 全員捕まれば鬼の勝ち。1 人でも時間切れまで残れば逃げる側の勝ち。

### 立ち回りの要点

- 見えていない相手は画面に描かれない。最後に見た位置にリングだけが残る。
- ロックされた箱は相手チームには動かせないが、時間をかければ解除される。
  鬼にとってはロックされた箱が「この辺に隠れている」という手がかりになる。
- 大きい箱には地面から直接は登れない。低い箱・ランプ・ジャンプ台を踏み台にする。
- **箱はつかんだまま跳ぶと持ち上がる。**別の箱の上で手を離せば積み上がる。
  低い箱（1.3 m）は目線（1.4 m）より低いので単体では視線を止められないが、
  2 段に積めば 2.6 m になって初めて遮蔽になる。準備フェーズの 32 秒をどう使うかが変わる。
  ジャンプの頂点は 1.3 m なので、低い箱には跳んで載せられるが、
  大きい箱（2.2 m）の上に載せるにはジャンプ台が要る。
  積んだ 2 段は上面 2.6 m で、地面からは登れない（ここも踏み台かジャンプ台が必要）。
- 逃げる側は近距離なら背後の気配も察知できる。鬼は視界に頼るしかない。
- 走りながらジャンプすると少しだけ速い。跳ねて移動するのが基本。
- 鬼はスタミナの減りが速く、全力疾走を続けられない。振り切るならその隙を突く。
- 隅は「遠い」が「逃げ道が片側しかない」場所。籠もるなら開けた側を残しておく。

### アイテム

| | 効果 |
| --- | --- |
| 補給パック（緑） | スタミナ全回復＋しばらくダッシュ消費が軽くなる。両陣営が拾える |
| ジャンプ台（紫） | 踏むと高く跳ね上がる。高い箱や内壁の上に一度で乗れる |
| 煙幕（`Q`） | 逃げる側が 2 回まで。視線を遮る煙が数秒残り、追跡を断ち切れる |

## 構成

描画・入力を含まない決定論シミュレーションとして `src/core` を独立させてある。
同じシードと同じ入力列なら必ず同じ試合になるので、AI を描画なしで大量に対戦させられる。

```
src/
  core/      ゲーム本体（three.js にも DOM にも依存しない）
    game.ts     状態遷移と物理。step(actions) を 1/60 秒刻みで回す
    physics.ts  円 vs AABB の押し出し、視線判定
    vision.ts   誰が誰を見えているか
    arena.ts    シードからのフィールド生成
  ai/        ルールベース AI
    seeker.ts   追跡・巡回・探索済みマップ・箱の排除
    hider.ts    拠点構築・箱の運搬とロック・逃走ステアリング
    nav.ts      グリッド A*（障害物が動くので定期的に作り直す）
    params.ts   戦術パラメータ（チューニング対象）
  render/    three.js での描画
  ui/        メニューと HUD、対戦ログの保存
  sim/       ヘッドレス対戦とパラメータ調整
    recorder.ts 試合の出来事をログ行にする（trace と画面の保存で共有）
```

## AI の調整

### 対戦させて測る

```bash
npm run sim -- --games 30 --hiders 2 --seekers 2
```

勝率、平均生存人数、最初に捕まるまでの時間、準備フェーズで固定できた箱の数が出る。

### 自動チューニング

片方の陣営のパラメータだけを揺らして自己対戦させ、勝率が上がった変更を採用する
（ランダム再スタート付きの山登り）。

```bash
npm run tune -- --side hider  --iters 40 --games 16 --hiders 2 --seekers 2
npm run tune -- --side seeker --iters 40 --games 16 --hiders 2 --seekers 2
```

結果は `src/ai/tuned.json` に書き出され、ゲームは起動時にこれを基準値へ重ねて読み込む。
両陣営を交互に回せば共進化する。`--dry-run` を付けると書き込まない。

`--games` は評価に使う試合数。ここを小さくすると、その少数のシードにだけ効く
パラメータが「勝率 100%」として採用されてしまう。採用後は必ず
`npm run sim` を別のシードで回して、勝率が保たれているかを確かめる。

調整するのはあくまで `src/ai/params.ts` の戦術パラメータで、
速度や制限時間といったゲームバランスは `src/core/config.ts` に置いてある。

## 今後の拡張

`src/core` が描画から切り離してあるので、`sim/headless.ts` の対戦ループをそのまま
学習ループに差し替えられる。観測（自分と相手の相対位置、視界の有無、箱の状態）と
行動（`Action` の 6 要素）はすでに構造体として定義済みなので、
方策を強化学習に置き換える場合も `ai/director.ts` の差し替えで済む。
