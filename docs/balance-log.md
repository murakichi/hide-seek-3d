# バランス変更の記録

改善サイクル（`/improve-seeker`、`/improve-hider`、`/improve-balance`）の
1 サイクルごとに追記する。勝率はすべて「逃げる側」のもの。

**測定のぶれについて。** 24 試合の勝率は 3v3 で 20 ポイント以上ぶれる（同じコードで
16.7% と 37.5% が出た）。144 試合でも、1v1 と 2v2 はシードによって改善と悪化が
入れ替わることがある。採否の判断は**最低 300 試合、かつ 1v1 / 2v2 / 3v3 の
3 構成が同じ向きに動いているか**で行うこと。24 試合は「異常終了しないこと」の確認用。

## 2026-08-10 逃走中の方向決めの振れを抑える

- 変更: `fleeDirection` に「直前のティックで選んだ方向から離れるほど減点する」項
  （`fleeTurnCost`、既定 30）を追加。`npm run tune` の探索対象にも入れた（範囲 [0, 60]）。
- 理由: `_probe` で、逃走モード中の平均速度が逃げる側 8.45 m/s に対して鬼 8.81 m/s だった。
  最高速度は逃げる側が上（9.4 対 8.8）なのに、実際に追われている間は遅い。
  毎ティック 24 方向を採点し直すため選択が隣の候補へ飛び移り続け、
  平均 10.7 度/tick・5.2% のティックで 90 度超の切り返しが起きていた。
  修正後は 6.4 度/tick、平均速度 9.05 m/s（鬼 9.00）で、鬼を上回った。
- 勝率: 1v1 23.0% / 2v2 36.3% / 3v3 40.0%（前回: 20.3 / 28.3 / 33.3）
  1v1・2v2 は各 300 試合、3v3 は各 180 試合（3 シード）。`fleeTurnCost` を
  0 / 14 / 30 と振ると 3 構成すべてで単調に上がった（平均 27.3 → 30.4 → 33.1%）。
  30 でもまだ頭打ちになっていない。
- 注意: **24 試合の勝率は 3v3 で 20 ポイント以上ぶれる。**
  同じコードが 24 試合で 16.7%、80 試合で 37.5% になった。144 試合でも、
  1v1 と 2v2 はシード次第で改善と悪化が入れ替わった。
  採否の判断は最低 300 試合、かつ 3 構成の向きが揃うかで見ること。

## 2026-08-11 逃げ道の多い場所を優先する案は不採用（変更なし）

- 変更: **なし。** `fleeDirection` に「着地点から走り出せる向きの割合」を加点する項
  （`fleeOpenWeight`）を試したが、測って取り下げた。`npm run sim` に `--seed` だけ追加。
- 理由: 3 構成すべてで単調に悪化した（各値 120 試合 / 3 シード、3v3 は 90 試合）。

  | fleeOpenWeight | 1v1 | 2v2 | 3v3 |
  | --- | --- | --- | --- |
  | 0（現状のまま） | 53.3% | 65.0% | 65.6% |
  | 40 | 41.7% | 55.8% | 53.3% |
  | 80 | 26.7% | 57.5% | 48.9% |

  開けた場所は逃げ道が多いと同時に鬼から見通せる場所でもあり、`fleeCoverBonus` と
  逆を向く項を足していた。詳細は `docs/journal/2026-08-11.md` と issue #002。
- 勝率: 変更なしなので 1v1 53.0% / 2v2 55.0% / 3v3 56.0% のまま（issue #003 の実測値）。

## 2026-08-10 見失った鬼の方へ帰らないようにした

- 変更: 逃走を解いたあとの待機・帰還で、目的地までの道のりが「直近に鬼が居た場所」へ
  近づくなら、その移動をやめて離れる向きへ退くようにした（`hider.ts` の `evade`）。
  逃走判定の `knownThreats`（記憶 4 秒）とは別に、判断用の記憶
  `threatMemory`（10 秒）と、割ってはいけない距離 `threatKeepAway`（10 m）を追加。
- 理由: `_probe` で、1v1 の捕獲 21 件のうち **76.2% が「捕まる直前 1.5 秒に鬼へ向かって
  走っていた」**、捕獲地点は拠点から平均 6.6 m だった。逃走判定の記憶が 4 秒で切れると
  `evade` は「拠点へ帰る」分岐に落ち、鬼と拠点の間に自分が居る形（逃げた直後は必ずこうなる）
  だと最短経路で鬼の正面に出ていた。修正後は同じ指標が 12.5%、捕獲地点と拠点の距離は 17.8 m。
- 勝率: **1v1 53.0% / 2v2 55.0% / 3v3 56.0%（前回: 24.7 / 35.3 / 40.0）。各 300 試合。**
  この数字はマージ時に `fleeTurnCost` 込みの master を取り込んだうえで測り直したもの。
  作業中は 24 試合 ×2 シードで 39.6 / 43.8 / 52.1 と読んでおり「3v3 だけ超過」と
  結論しかけたが、300 試合では **3 構成すべてが目標帯（35〜50%）の上**だった。
  超過幅は 1v1 +3 / 2v2 +5 / 3v3 +6 で、人数が増えるほど大きい。
  初補足までの時間も 1v1 で 49.4 → 64.0 秒と伸びており、鬼が見つけられていない。
  逃げる側を弱めて帳尻を合わせる話ではないので、鬼側の課題として issue #003 に立てた。

## 2026-08-10 逃走中の硬直を解消

- 変更: `fleeDirection` が「どの向きにも走れる幅が無い」と判断したときに
  移動入力を空で返していたのをやめ、一番遠くまで進めて脅威から離れる向きへ押し込むようにした。
  速度が出ない状態が続いたら乗り越えも試みる。
- 理由: `_probe` で、3v3 の追跡フェーズのうち 4.7% のティックで逃走者の移動入力が
  ゼロになっており、その大半が箱の近くだった。最長で 32.3 秒その場に固まっていた。
  1v1 では硬直は 0% で、こちらは純粋に追いつかれている（原因が別）。
- 勝率: 1v1 12.5% / 2v2 25.0% / 3v3 29.2%（前回: 12.5 / 33.3 / 16.7）
  3v3 の平均生存人数は 0.25 → 0.46。硬直ティックの割合は 4.7% → 0%。

## 2026-08-10 遊び心地の調整

- 変更: 移動速度を 6.6 → 9.4（鬼 8.8）に引き上げ、アリーナを 36x36 → 44x44 に拡大。
  ジャンプに踏み切りの推進力を追加、ジャンプ台を設置。逃げる側に煙幕（2 回）を追加。
  鬼のダッシュ消費を逃げる側の 1.5 倍にした。拠点の評価に隅のペナルティを追加。
- 理由:
  - 速度を上げただけでは逃げ側勝率が落ちた（AI の先読み距離が旧速度のままで壁に突っ込んでいた）。
    `fleeDirection` のレイと `followPath` の到達判定を速度に合わせて伸ばして回復。
  - トレースで、拠点が隅（壁まで 1.9 m）に選ばれ、追跡開始 1.1 秒で発見されて
    逃げ道が無いまま捕獲される試合を確認。「中央から遠いほど良い」の評価が隅を選ばせていた。
- 勝率: 1v1 12.5% / 2v2 33.3% / 3v3 16.7%（前回: 12.5 / 20.8 / 25.0）

## 2026-08-10 初期構築

- 変更: ルールベース AI 一式、拠点の分散、補給パック、ジャンプ台、移動速度の引き上げ。
- 理由: トレースで判明した主な欠陥は次の 3 つ。
  - 逃げる側が状態遷移のたびに入力を空で返し、1 ティックおきに停止していた。
  - 掴んだ箱を衝突解決の後に動かしていたため、押している本人に押し戻されて箱が永久に動かなかった。
  - 準備フェーズの経路が中央のケージを突っ切り、境界に押し戻されて追跡開始まで動けなかった
    （拠点まで届かず、開幕 2.4 m の距離で即捕獲されていた）。
- 勝率: 1v1 12.5% / 2v2 20.8% / 3v3 25.0%

### 未解決

- 1v1 の逃げ側勝率が低い。他構成より 10 ポイント以上低く、原因は未特定。
- 目標はどの構成でも 35〜50%。
