# 001 1v1 の逃げ側勝率が低い

## 症状

24 試合で 12.5%。2v2 が 25.0%、3v3 が 29.2% なので、1v1 だけ明らかに低い。
初補足までの時間は 50.1 秒（準備 32 秒 + 追跡 18 秒）。

## 分かっていること

- **硬直は原因ではない。** `npm run tune` 前の `src/sim/_probe.ts` による計測で、
  1v1 の追跡フェーズ中に移動入力がゼロになるティックは 0%（3v3 は 4.7% あった）。
  逃げてはいるが追いつかれている。
- 人数別に見た「個人あたりの生存率」は 1v1 12.5% / 2v2 12.5% / 3v3 11% でほぼ一定。
  つまり多人数戦の勝率が高いのは「誰か 1 人が残れば勝ち」というルールの効果であり、
  1 対 1 の逃げ切り能力そのものは人数によらず低い。
- 速度差は逃げ側 9.4 / 鬼 8.8。鬼のダッシュ消費は 1.5 倍にしてあるが、
  この変更で勝率は動かなかった（12.5% のまま）。
- 拠点が隅に選ばれる問題は修正済み（壁際にペナルティ）。それでも 1v1 は改善しなかった。

- **速度負けが原因の一つだった**（2026-08-10 追記）。
  逃走モード中の平均速度を測ると、修正前は逃げる側 8.45 m/s に対して鬼 8.81 m/s で、
  最高速度が上（9.4 対 8.8）なのに実際には遅かった。原因は `fleeDirection` が
  毎ティック 24 方向を採点し直して選択が飛び移り続けていたこと（平均 10.7 度/tick、
  5.2% のティックで 90 度超の切り返し）。加速し切る前に向きが変わるので速度が乗らない。
  `fleeTurnCost` を入れて 9.05 m/s（鬼 9.00）まで回復。1v1 の勝率は 20.3% → 23.0%
  （各 300 試合、`fleeTurnCost` 0 → 30）。**ただし目標の 35〜50% には遠く、
  これ単体では解決しない。** 2v2 28.3 → 36.3、3v3 33.3 → 40.0 と、
  伸び幅は 1v1 が最も小さい。1v1 固有の要因がまだ残っている。
- **1v1 の勝率は 12.5% ではなく 20% 前後だった**（2026-08-10 追記）。
  24 試合の測定値がぶれていただけ。80 試合（40 × 2 シード）で測り直すと修正前 22.5%。
  この issue の症状欄の数字は過小。判断は最低 80 試合で行うこと。

## 分かっていないこと

- 速度が足りているのに捕まるなら、負けているのは**位置取り**のはず。
  トレースでは逃走が壁沿いの南北往復になり、折り返すたびに鬼の前を横切っていた
  → issue #2 に切り出した。まずそちらを潰す。
- 煙幕（2 回）が実戦で使われているか、使って効果が出ているか。未計測。
  seed=1234 の負け試合トレースには煙のイベントが 1 度も出ていない。
- 準備フェーズの後半 12 秒（t=20〜32）が `idle` で捨てられている。
  置き場所が全部埋まると次の仕事が無くなる。この時間を使えていない。

## 解決

2026-08-10。**逃げる側が自分から鬼へ戻っていた**のが原因。

`_probe` で数えたところ、1v1 の捕獲 21 件のうち 76.2% が「捕まる直前 1.5 秒に鬼へ
向かって走っていた」状態で、捕獲地点は拠点から平均 6.6 m だった。速度負けではなかった。

`evade` の逃走判定に使う `knownThreats` は記憶を 4 秒しか持たない。切れた瞬間に
「脅威なし」の分岐へ落ちて拠点へ最短で帰るが、逃げた直後は必ず
「鬼と拠点の間に自分が居る」形になっているので、帰路が鬼の正面を通っていた。
1v1 で顕著なのは、鬼が 1 人しかいない＝視線が切れやすく、記憶切れが頻繁に起きるため。

修正は、待機・帰還・補給のいずれの移動でも、目的地までの道のりが「直近に鬼が居た場所」
（判断用の記憶 `threatMemory` = 10 秒）へ近づく形で `threatKeepAway`（10 m）を割るなら
その移動をやめ、離れる向きへ退くようにした。

- 同じ指標: 捕獲直前に鬼へ詰めていた割合 76.2% → 12.5%、捕獲地点と拠点の距離 6.6 → 17.8 m
- 勝率 1v1 12.5% → 33.3%、2v2 25.0% → 50.0%、3v3 29.2% → 62.5%
- 別シード（90210）でも 25.0 → 45.8 / 29.2 → 37.5 / 25.0 → 41.7

3v3 が目標帯の上に出た件は issue #003 へ。
