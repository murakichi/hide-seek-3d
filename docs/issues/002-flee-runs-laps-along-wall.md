# 002 逃走が壁沿いの往復になり、鬼の前を何度も横切る

## 症状

1v1 の負け試合（seed=1234）のトレース。逃走者は追跡フェーズの 17 秒間、
アリーナ東端（x ≈ 15〜17）を南北に往復し続け、そのたびに鬼に再発見されている。

```
[追跡開始] t= 32.0   逃#0 は (15.4,-8.1) に潜伏
  発見   t= 33.8  (16.7, -9.0) 距離 14.1
  見失い t= 34.1  (16.3, -8.1)
  発見   t= 35.3  (15.5, -0.1) 距離 12.7     ← 北へ
  見失い t= 36.5  (14.6,  9.4)
  発見   t= 42.7  (16.3, -3.6) 距離 10.8     ← 南へ折り返して鬼の正面
  見失い t= 43.9  (17.2,-14.1)
  捕獲   t= 48.9  (14.4,-14.6)
```

見失いは 3 回起きているので遮蔽そのものは機能している。
にもかかわらず、折り返すたびに同じ縦のラインへ戻って再発見されている。

## 分かっていること

- `fleeDirection` は「鬼から遠ざかる」「壁から離れる」「進める距離」で毎ティック方向を選ぶ。
  評価するのは**その瞬間の位置**だけで、行き止まりに向かっていることを見ていない。
  端まで走ると壁ペナルティで折り返し、来た道を戻ることになる。
- 方向の振れ自体は #001 の修正（`fleeTurnCost`）で 10.7 → 6.4 度/tick に減った。
  往復はそれとは別で、「長い直線を選び続けた結果」なので churn では説明できない。
- 見失ってからの逃走先に「鬼の最後の目撃位置から離れる」という考慮が無い。
  鬼の記憶（`memory.hider`）は 4 秒で切れるので、切れた瞬間に鬼の位置を忘れて
  平気で元の方向へ戻る。

### 2026-08-11 追記: 現象は実在した（各 40 試合、`_probe`）

トレース 1 本ではなく全試合で数えた。往復は確かに起きていて、発見とも強く相関している。

| | 1v1 | 3v3 |
| --- | --- | --- |
| 逃走中に壁まで 6m 未満 | 48.7% | 73.8%（面積比なら 47%） |
| 往復（6〜20 秒前の位置へ 5m 以内に戻った） | 238 回 | 426 回 |
| **発見のうち直前 3 秒に往復していた** | **46.1%** | **38.5%** |
| 捕獲地点の壁までの距離 | 5.3m | 3.9m（一様なら 7.3m） |

1v1 の壁沿い率 48.7% は面積比とほぼ同じなので「壁に貼り付いている」とまでは言えないが、
**3v3 の 73.8% は明らかに過剰**で、捕獲地点はどちらも壁寄りに偏っている。
発見の 4 割前後が往復の直後に起きているのも事実。

### 2026-08-11 追記: 煙幕は使えている（未計測項目への回答）

1v1 で 40 試合あたり 75 回、3v3 で 217 回使われており、捕獲時点で残っているのは
平均 0.16〜0.26 回ぶん。つまり**撒く条件は厳しすぎず、ほぼ撃ち切っている**。
煙幕はこの issue の原因ではない。

## 試して駄目だった案

- **着地点の「開けている度合い」を加点する（`fleeOpenWeight`）** — 2026-08-11。
  `fleeDirection` の採点は着地点の一瞬しか見ておらず、鬼から離れる項が最大 80 点前後と
  支配的なので、まっすぐ壁へ走るコースが最高得点になりやすい。そこで着地点から
  8 方向へ 7m のレイを飛ばし、走り出せる向きの割合（0〜1）に重みを掛けて加点した。
  結果は**3 構成すべてで 0（入れない）が最良**（各値 120 試合 / 3 シード、3v3 は 90 試合）。
  ただし単調ではなく、2v2 は 40 より 80 の方が高い（55.8 → 57.5）。
  重みの大きさより「この項を入れるかどうか」が効いている:

  | fleeOpenWeight | 1v1 | 2v2 | 3v3 |
  | --- | --- | --- | --- |
  | 0（現状） | 53.3% | 65.0% | 65.6% |
  | 40 | 41.7% | 55.8% | 53.3% |
  | 80 | 26.7% | 57.5% | 48.9% |

  1v1 は 3 シードすべてで下がった（52.5/57.5/50.0 → 22.5/35.0/22.5）。
  **示唆**: 開けた場所は逃げ道が多いと同時に、鬼から見通せる場所でもある。
  この AI にとっては「逃げ道の数」より「視線が切れること」の方がはるかに価値が高い。
  往復は下手な動きに見えるが、実際には遮蔽のある一角に留まる動きであり、
  それ自体は悪手ではない可能性が高い。**往復＝悪手という前提を疑うべき。**

## 分かっていないこと

- 折り返しを禁じる（一定時間は同じ半平面から出ない）だけで改善するのか。未検証。
  ただし上の結果から、「往復をやめさせる」方向の修正は逆効果になりやすい。
- 往復と発見の相関（46.1%）が因果なのかどうか。遮蔽のある一角に留まれば、
  往復もするし、鬼もそこを繰り返し探しに来るので、両方が同じ原因から出ている可能性がある。

## 優先度について（2026-08-11 に medium → low）

逃げる側の勝率は現在 1v1 53.0% / 2v2 55.0% / 3v3 56.0% で、**目標帯 35〜50% の上**
（issue #003）。この issue を直すと逃げる側がさらに強くなるため、今の順序では着手しない。
着手するなら「勝率を上げずに動きの見栄えだけ直す」形に限る。
