# 002 逃走が壁沿いの往復になり、鬼の前を何度も横切る

## 症状

1v1 の負け試合（seed=1234）のトレース。逃走者は追跡フェーズの 17 秒間、
アリーナ東端（x ≈ 15〜17）を南北に往復し続け、そのたびに鬼に再発見されている。

```
[追跡開始] t= 32.0   逃#0 は (15.4,-8.1) に潜伏
  発見   t= 33.8  (16.7, -9.0) 距離 14.1
  見失い t= 34.1  (16.3, -8.1)
  発見   t= 35.3  (15.5, -0.1) 距離 12.7     ← 北へ
  見失い t= 36.5  (14.6,  9.4)
  発見   t= 42.7  (16.3, -3.6) 距離 10.8     ← 南へ折り返して鬼の正面
  見失い t= 43.9  (17.2,-14.1)
  捕獲   t= 48.9  (14.4,-14.6)
```

見失いは 3 回起きているので遮蔽そのものは機能している。
にもかかわらず、折り返すたびに同じ縦のラインへ戻って再発見されている。

## 分かっていること

- `fleeDirection` は「鬼から遠ざかる」「壁から離れる」「進める距離」で毎ティック方向を選ぶ。
  評価するのは**その瞬間の位置**だけで、行き止まりに向かっていることを見ていない。
  端まで走ると壁ペナルティで折り返し、来た道を戻ることになる。
- 方向の振れ自体は #001 の修正（`fleeTurnCost`）で 10.7 → 6.4 度/tick に減った。
  往復はそれとは別で、「長い直線を選び続けた結果」なので churn では説明できない。
- 見失ってからの逃走先に「鬼の最後の目撃位置から離れる」という考慮が無い。
  鬼の記憶（`memory.hider`）は 4 秒で切れるので、切れた瞬間に鬼の位置を忘れて
  平気で元の方向へ戻る。

## 分かっていないこと

- 折り返しを禁じる（一定時間は同じ半平面から出ない）だけで改善するのか、
  それとも「見失ったら遮蔽の裏で止まる」まで必要なのか。未検証。
- 煙幕が使われているか。`fleeDirection` とは別条件（`nearest < 8` かつ被視認）で撒くが、
  上のトレースには煙のイベントが 1 度も出ていない。実戦で使えているか未計測。
